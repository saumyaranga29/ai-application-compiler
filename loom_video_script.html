Section 2: Compiler Pipeline & Local Mock Engine
1:00 - 2:30
Visual Focus: Open backend/pipeline.js and backend/mockGenerator.js in VS Code, or trigger a compiler run in the browser and show the 4 stages animating in the Logs panel.
"To ensure predictable structures, the compiler executes a modular four-stage pipeline, much like a traditional language compiler.

1. Stage 1 (Intent Extraction): Parses the instruction into structured pages, features, roles, and database entities.
2. Stage 2 (System Design): Maps features to UI screens, database tables, and REST API endpoints.
3. Stage 3 (Schema Generation): Generates concrete UI configurations, DB schemas, and auth matrices.
4. Stage 4 (Refinement): Resolves relational consistency.

We also developed an offline mock compiler engine in mockGenerator.js. If the Gemini API key is missing or calls fail due to transient errors, the pipeline automatically routes requests to this local engine, mimicking the 4 compiler phases with realistic timing delays and ensuring 100% server resilience."
Section 3: Cross-Layer Validation & Self-Healing
2:30 - 3:30
Visual Focus: Highlight the cross-layer relationships in backend/validator.js (line checking GET endpoints and POST actions) and the repair loop in pipeline.js.
"The heart of this system is the Static Validation & Repair Engine located in backend/validator.js. It enforces cross-layer relational integrity:

- It guarantees that every UI page component dataSource references a valid GET API endpoint.
- It verifies that every CRUD table action corresponds to valid POST, PUT, or DELETE API routes.
- It verifies that all database tables have auto-incrementing integer primary keys.

If validation errors are found, the compiler doesn't blindly retry the full generation. Instead, it captures the exact error details and feeds them along with the draft schema back to the LLM. It runs up to 3 targeted repair attempts to heal the schema surgically. If the final output cannot satisfy the validator, the compile fails."
